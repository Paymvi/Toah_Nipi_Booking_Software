# Tutorial Gnome: UX Audit

Audit date: 2026-11-04 · Branch: `main` (uncommitted changes) · Base commit: `f1c32b0`

## Scope and method

**Scope:** All 5 tutorials in `src/tutorial/tutorials.js`, in both modes: **Guided** ("Walk me through it") and **Demo** ("Show me how"). The review also covered the engine (`TutorialRunner.jsx`, `tutorialCore.js`), the gnome styles (`TutorialGnome.css`) and the screens each step describes (`CreateBooking.jsx`, `SpreadsheetView.jsx`, `Dashboard.jsx` booking profile, `CalendarView.jsx`, `ContactsView.jsx`).

**Demo data:** The codebase has no demo fixtures. Demo mode runs on whatever bookings are loaded. It never types anything: example values appear only in the gnome's dialogue, labelled "Example". It clicks only navigation, tabs, view switches and, after this change, Edit Entry. So the fixes keep examples consistent with each other and with what each field accepts, and the demo text now says plainly when it opens "the first group on the list".

All tutorial examples use one fictional booking: **Community Bible Church**, led by **Jordan Smith**, Retreat Type **Church**, arriving June 5 and leaving June 7, about 45 guests. The Contacts search example is the same leader, and the spreadsheet search example is the same group.

**Method:**
1. **Code inspection.** Each step's text, example, target and `done` check was compared with the screen it points at: field labels, option lists, which fields search covers, and what buttons actually do.
2. **Browser walkthroughs.** These used real Chrome through `playwright-core`, against a local Vite dev server and a local mock Supabase. The mock held three fictional bookings: Community Bible Church / Jordan Smith (made with the Form), and Grace Fellowship Youth / Ava Lee and Lakeside Women's Retreat / Mia Chen (imported). All non-localhost network requests were blocked, so no production data could be read or written. The mock logged every write request, and none were made in any run.
   - Every tutorial ran in Demo mode at 1440×900 and 390×800. Each step's dialogue text, highlighted element and route were recorded, with screenshots.
   - Guided flows were exercised: typing into fields, clicking targets, Skip, Next, Back, Restart, End and reopening from the library, Finish.
   - Edit was tested on both kinds of booking: made with the Form, and imported.
   - A fit check ran every step of every tutorial, in both modes, at 390×800 and in Guided mode at 360×640.
   - The previous tutorial session's end-to-end suite was re-run.

"Browser" in the status column means the issue was seen in the running app, before and after the fix. "Code" means it was found and fixed by reading the code.

## Unresolved issues and verification limits

- **No isolated demo data.** Demo mode shows real loaded records and never types its examples. Making the demo display fictional matching rows would mean injecting fake records into live views, which is a redesign with a risk of staff mistaking them for real bookings. Instead, the wording now states when the demo opens "the first group/contact on the list".
- **Inquiry Record Detail Back** (`Dashboard.jsx`, `navigate("/inquiry-spreadsheet")`) follows the same pattern as TG-11, so it likely shows the same empty "no booking" page. No tutorial covers it, so it was left unchanged and not browser-tested.
- **Contacts history at 390 px:** the "Open Booking" button inside the history panel is clipped by the table's horizontal scroll. This is app layout, not tutorial content, so it was not changed.
- **Practice search persists** (TG-10). It is explained, not changed: clearing a person's saved spreadsheet search automatically could remove a filter they set on purpose.
- **Test environment:** local mock Supabase with three fictional bookings, desktop Chrome only (emulated mobile viewport, touch enabled). Not tested against production data, Safari/Firefox, or a physical phone.
- **Previous end-to-end suite** (from the session that built the gnome; it lives in a temporary folder, not in the repo): all sections pass. These cover guided create/open/edit/calendar, demo create/contacts, pause/resume, missing-target recovery, keyboard, reduced motion, mobile, login screen, and no database writes. Three of its selectors had gone stale and were fixed first: the old caption text, a `/Back/` button match that also hit "Backup", and a click made before the step became active.
- **Lint:** `npm run lint` reports 77 problems, the same 77 as before these changes (pre-existing, mostly `react-hooks/set-state-in-effect`). The changed tutorial files lint clean.

## Summary of improvements

- **Examples now teach the task.** Search examples are a real group name and a real (fictional) person's name, consistent across tutorials. The Retreat Type example is an actual option, dates no longer carry wrong weekdays, and the edit example names a field that's on screen.
- **Words, highlights and actions agree.** The imported-booking demo unlocks the fields before describing Save. Cancel is only promised where it exists, and the Overview stats and sections are described as they actually behave.
- **Navigation is safe to explore.** The gnome's Back can no longer strand someone on a step from another screen. Going back in a demo no longer undoes the screen, and Restart from inside a booking explains how to get back.
- **The booking Back button now works when opened from the Master Spreadsheet.** It used to show "No booking selected".
- **Small screens:** highlighted controls at the end of a page scroll above the docked dialogue, and the gnome's buttons always stay visible.
- Changes stay inside the tutorial library, runner and styles, plus the one-line Back fix. The gnome's look, personality, practice-save guard and demo click rules are unchanged; Edit Entry is the only control added to demo clicks, and it only unlocks the fields.
